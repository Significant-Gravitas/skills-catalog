# Booking a loop

- [ ] Loop shape confirmed: slots, lengths, competency per slot, where the
      breathing room goes (default 10-minute buffers and a proper break near
      the midpoint for a four-slot onsite; confirm with the owner).
- [ ] Candidate windows and zone from the candidate; panel free/busy read
      (read-only) or pasted; `availability.json` written.
- [ ] `tz_slots.py` run; two or three options shown verbatim, strongest
      first, each with its one compromise; both zones on every slot.
- [ ] After the pick: exactly what to write asked (holds, invites, table).
- [ ] Every calendar write validated, described, and approved; results
      reported only after success.
- [ ] Candidate email, interviewer notes and holds handed over together;
      the process map (every stage, who, when a decision comes) matches the
      one set at the screen.
- [ ] `loops.csv` updated; tracker written back; counts reported.

# Stall sweep / morning brief

- [ ] `merge_tracker.py refresh` then `stall_sweep.py` (history on, unless previewing).
- [ ] Grouped by holder, oldest first, one action each, a nudge drafted per item.
- [ ] Second stalls escalated with days lost and the effect on the loop.
- [ ] Anyone past the response window has a holding update drafted.
- [ ] Brief under 200 words; nothing sent; candidate details not in a group channel.

# Any decline

- [ ] Background-check question asked; FCRA route if yes or not sure.
- [ ] Decision in the first two sentences; only approved feedback; phone
      talking points if late-stage.
